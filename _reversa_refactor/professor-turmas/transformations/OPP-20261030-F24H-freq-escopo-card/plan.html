OPP-20261030-F24H decouple gate pendente

Contexto: professor-turmas | Arquivos alvo: src/views/professor-turmas.ts, src/views/professor-turmas-frequencia.ts | Data: 2026-10-30

1. Problema

O módulo de frequência não conhece o card da turma que está operando. Ele lê dois IDs fixos (freq-data e freq-disciplina) pelo document global. Como a view repete esses IDs em cada card, getElementById sempre devolve o primeiro card do documento.

card Turma A: id freq-data e card Turma B: id freq-data (duplicado) -> document.getElementById retorna sempre o card A

Consequência: salvar a frequência do card B envia a data e a disciplina selecionadas no card A. Carregar frequência existente no card B também consulta a disciplina do card A.

2. Acoplamento medido

6 chamadas a document.getElementById no módulo de frequência
2N IDs duplicados no documento (2 por card de turma)
2 símbolos globais dos quais o módulo depende (freq-data, freq-disciplina)
0 dependências globais depois da costura
0 IDs duplicados depois da costura
1 resolvedor escopado por card (camposFrequencia)

3. Costura proposta

Criar uma função interna que resolve os campos a partir do container já recebido e do turma.id já recebido, subindo até o .turma-card correspondente. Nenhum novo import e nenhuma mudança no grafo de módulos.

// professor-turmas-frequencia.ts
function camposFrequencia(container: HTMLElement, turma: TurmaGroup) {
  const freqList = container.querySelector(`.frequencia-list[data-turma-id="${turma.id || ""}"]`) as HTMLElement | null;
  const card = freqList?.closest(".turma-card") as HTMLElement | null;
  return {
    freqList,
    dataInput: card?.querySelector(".freq-data-input") as HTMLInputElement | null,
    discInput: card?.querySelector(".freq-disc-input") as HTMLSelectElement | null,
  };
}

view Os campos ganham classes estáveis e IDs únicos por turma:

- <label class="label" for="freq-data">Data da Aula</label>
- <input type="date" id="freq-data" class="input" ...>
+ <label class="label" for="freq-data-${chave}">Data da Aula</label>
+ <input type="date" id="freq-data-${chave}" class="input freq-data-input" ...>

- <label class="label" for="freq-disciplina">Disciplina</label>
- <select id="freq-disciplina" class="input" ...>
+ <label class="label" for="freq-disciplina-${chave}">Disciplina</label>
+ <select id="freq-disciplina-${chave}" class="input freq-disc-input" ...>

chave = turma.id || "sem-turma", calculada no início da iteração de turmas.map.

4. Comportamento

atenção Esta costura corrige um comportamento observável errado. O contrato preservado é: cada card usa os próprios campos, o mesmo turma.id, os mesmos alunos ativos e o mesmo fallback de data. O que muda é o alvo do card 2 em diante, que passa a ser o correto.

O gate precisa aprovar explicitamente essa correção. Sem isso, o especialista recusa a aplicação.
